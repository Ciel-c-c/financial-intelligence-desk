# 证据优先的新闻解读流程

日期：2026-09-17。范围：现有完整正文的自动解读后台；不修改页面 UI，不把行情或来源覆盖尚未完成的问题宣布为已解决。

## 已确认目标

复用 Groq 免费账户及现有密钥。把一次生成整篇解读改为“原文证据抽取 → 机制分析 → 校验发布”。保留现有新闻详情、所以呢、每日简报和全球局势的数据接口。不得启用付费回退。

## 方案取舍

继续增加一次性生成提示词，改动小，但事实和推演仍混在一起；纯规则模板成本低，但难以表达不同事件的真实机制。采用分阶段模型处理，并以代码验证证据和接口，便于定位失败，不能把同一模型复审视为独立事实核验。

## 阶段一：证据抽取

输入只包含白名单来源、原文标题、发布时间、链接和已读取的完整正文。正文是数据，不接受其中的指令。

输出事实清单，每条包含事实转述及原文短引文；另行抽取事件主体、地区、行动、背景、报道中明确出现的市场预期和不确定因素。背景与市场预期也必须附原文短引文，未报道则为空，禁止补写“市场原本预期”。

代码检查结构、引文确实存在于正文、事实数值和实体的来源依据。证据必须绑定原文 URL、发布时间和正文哈希。证据通过才能进入下一阶段；引文存在不等于转述必然正确，最终审核仍检查语义。

## 阶段二：机制分析

输入已校验的证据清单及原文供核对；不允许修改来源信息和已核验事实。生成现有专业解释、条件性推演、风险、3–6 节点因果链及所以呢各字段。

明确区分报道事实、一般机制和本次推断。没有报道中的预期依据时，说明无法确认原先共识，转而提出需要观察的问题；不得杜撰概率、阈值或一致预期。相邻节点须有因果关系，不能拼接并列事件。利率不变不等于融资成本下降，债券出售不等于发行。

个人影响在投资、汇率、住房、工作、消费、企业经营中按地区、事件、证据和传导关系选择，通常 2–5 项，确实只有一个强相关维度允许 1 项。每项回答影响什么、为什么、什么情况下不成立；不为凑数增加弱相关项。英文来源优先生成中文，合格英文结果可明确标识保留，不把仅翻译标题视作完整解读。

## 阶段三：审核与原子发布

代码校验原接口完整性、数字与预期证据、语言一致性和身份绑定；模型审核转述准确性、传导逻辑、类比和反例。任一步失败均不发布半篇解读。只把通过结果组装进现有 editorial，保留可核验的短引文与事实对应关系，不公开转载完整报道正文。

每日简报、政策事件和全球局势继续从同一个通过的 editorial 派生，不能只更新事实而复用另一事件的旧分析。失败保留已有合格内容及原新闻日期，不标成今日重点。

## 免费预算及失败处理

每轮最多尝试 2 篇、最多 6 次模型请求，沿用至少 60 秒请求间隔和单请求超时，在现有 12 分钟任务内留出抓取、验证和提交时间。401/402/403/429 停止模型调用，不升级付费、不无限重试。成功结果继续按正文哈希复用。

公开健康信息区分 API 连通、证据通过、分析通过和发布数量。全部候选被拒绝不得显示为解读成功。拒绝记录阶段及安全的原因码，不记录密钥或完整模型响应。候选选择轮换，避免同一批失败文章持续阻塞其他候选；重试状态以来源 URL 和正文哈希绑定、限次保存，不存储全文。

## 验收

用测试覆盖：无引文、虚构数字、虚构共识、错误事件绑定、链条跳步、个人影响成立条件冒充反例、英文回退、额度耗尽、缓存及候选轮换。先运行测试和数据验证，再执行真实 Actions 任务，人工对照全文检查至少一条实际输出。若没有合格输出，明确报告未验收，不能只凭任务绿色宣布完成。

部署后检查公开数据与页面的同一条内容、可点击详情、日期和派生关系；确认 UI 资源未因本次后台改动改变。完成通知只在真实内容及部署均核验后发送。
