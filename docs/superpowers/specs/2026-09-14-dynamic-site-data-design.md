# Financial Lens 全站动态数据化设计

日期：2026-09-14  
状态：已确认，待实施计划

## 1. 背景

当前网站只有新闻流和部分全球事件具备动态快照能力。首页市场总览、A股/港股/美股/全球资产、行业强弱、市场摘要、核心传导和市场简报仍直接或间接读取 `src/data/demoData.ts`；全球局势在动态数据不可用时会回退种子事件。现有 `market-snapshot.json` 虽然每小时更新，但只含 ECB 欧元参考汇率，且首页没有读取它。

因此，“数据任务成功”不等于“全站内容已更新”。本项目需要建立统一的数据状态和页面消费规则，使用户能明确知道每项内容的数据时间、来源、延迟程度及失败原因。

## 2. 目标

- 首页、市场简报和全球局势全部读取经过验证的动态快照。
- 动态覆盖 A股、港股、美股、全球资产及对应行业相对表现。
- 市场摘要、核心传导和每日简报基于同一批有效数据生成。
- 所有公开数据可追溯到官方或经核验的知名机构。
- 数据不足或失败时明确显示缺失或延迟，不再以演示数据冒充今日内容。
- 统一处理 GitHub Pages、浏览器和 Service Worker 缓存，页面能及时发现新快照。
- 保留现有 Financial Lens 视觉语言与新闻详情「所以呢？」体系。

## 3. 非目标

- 不提供毫秒级或交易执行级实时行情。
- 不承诺覆盖所有证券、公司或行业。
- 不使用来源不明的隐藏接口、转载聚合站或弱来源凑数。
- 不自动编造市场涨跌原因。
- 不把静态学院课程改造成实时内容；只动态更新其中的“今日案例”。
- 不大范围重写无关页面或设计系统。

## 4. 数据来源方案

采用“官方 + 经核验的知名公开市场数据源”混合方案。

优先级：

1. 交易所、指数公司、央行、财政和统计机构的公开数据。
2. FRED、ECB、EIA 等知名官方数据库。
3. 具有稳定公开接口、明确标的定义和使用条件的知名市场数据机构。

正式接入前逐项验证：发布主体和域名、标的定义、币种、交易日、时间戳、复权及涨跌幅口径、频率限制、缓存和展示许可。验证结果记录在来源注册表；未经验证的来源不得启用。每个来源至少每 90 天复核一次，过期自动停用。

## 5. 总体架构

建立统一状态索引 `site-snapshot.json`，各业务数据继续使用独立文件：

```text
site-snapshot.json
├─ news-feed.json
├─ market-overview.json
├─ sector-performance.json
├─ global-situation.json
└─ daily-brief.json
```

数据流：

```text
白名单来源
→ 抓取
→ 来源与时间验证
→ 标准化
→ 数据集级校验
→ 原子发布独立快照
→ 更新全站状态索引
→ GitHub Pages 部署
```

各数据集独立失败，避免单一来源或单一市场拖垮全站。`site-snapshot.json` 只聚合健康状态，不复制业务数据。

## 6. 统一状态契约

每个数据集至少包含：

- `attemptedAt`：最近尝试更新时间。
- `lastSuccessfulAt`：最近成功更新时间。
- `dataAsOf`：数据本身对应时间。
- `nextExpectedAt`：下一次预计更新时间。
- `status`：`fresh`、`delayed`、`partial` 或 `unavailable`。
- `freshness`：`realtime`、`delayed`、`close` 或 `historical`。
- `sourceHealth`：来源级健康信息。
- `fallbackReason`：使用旧快照或缺失的原因。

页面不得使用部署时间代替数据时间，也不得用抓取时间代替行情时间。

失败策略：

- 单一来源失败：发布其余可靠数据，状态为 `partial`。
- 数据集整体失败：保留最后成功快照，状态为 `delayed` 并说明原因。
- 从未获得有效数据：状态为 `unavailable`，页面显示“暂无可靠数据”。
- 禁止用 `demoData.ts` 静默填充生产页面。
- 静态课程和明确标记的教学示例不受此限制。

## 7. 市场总览

固定观察池：

- A股：上证指数、沪深300、深证成指、创业板指。
- 港股：恒生指数、恒生国企指数、恒生科技指数。
- 美股：标普500、纳斯达克综合指数、道琼斯工业指数。
- 全球资产：美元指数、美国10年期国债收益率、黄金、原油和主要汇率；数字资产仅在可靠来源可用时补充。

单个市场标的包含：名称、代码、最新值、涨跌额、涨跌幅、币种或单位、市场状态、`dataAsOf`、来源名称和原始链接、`freshness`、最近成功获取时间。

交易状态规则：

- 盘中数据按来源能力标记实时或延迟。
- 收盘后标记“当日收盘”。
- 休市时标记“上一交易日收盘”。
- 数据超出允许时效时显示延迟，不统一写“今日”。
- 单项来源不可用时允许缺失，不以旧演示值补位。

## 8. 行业相对强弱

行业数据按当前市场切换，不能混合不同分类体系：

- A股使用一种明确且稳定的申万、证监会或中证行业口径。
- 港股使用恒生行业分类或明确标记的行业指数。
- 美股使用标准行业指数；若使用 ETF，必须标注“行业代理资产”。
- 全球资产页不展示股票行业排名，改为资产类别相对表现。

每项包含：行业名称、涨跌幅、排名、数据时间、分类标准、来源、可能驱动因素和驱动因素证据来源。

“为什么这样走”必须有当天新闻、政策或数据与行业之间的明确传导证据。证据不足时显示“暂无足够证据解释本次波动”，不能从涨跌方向反向编造原因。

移动端默认展示前 5 名和后 5 名，其余渐进展开。

## 9. 首页动态内容

首页顶部市场摘要由同一份有效快照计算：

```text
主要指数方向
→ 市场广度
→ 最强 / 最弱行业
→ 当天最相关的政策或经济事件
```

摘要分为事实层和解释层。事实层只描述实际数据；解释层只有在存在可靠事件和传导证据时出现。无法确认原因时只展示事实。

核心市场传导从当天高重要性新闻或全球事件中选择一条 3–6 步因果链。每一步包含机制，整条链包含条件或反例。当日没有足够强的事件时隐藏模块，不显示固定旧链路。

首页新闻继续使用已经部署的 24 小时新闻流和独立的 24–72 小时持续影响区域。

## 10. 每日市场简报

简报读取市场、行业、新闻和全球局势的同一批有效快照，结构为：

1. 今天发生了什么。
2. 主要市场如何表现。
3. 市场真正关注什么。
4. 关键因果链。
5. 接下来观察什么。
6. 哪些判断可能失效。

每天生成两个版本：

- 北京时间早间版：隔夜美股、全球资产和当天政策日程。
- 主要市场收盘版：A股、港股、欧洲市场及当日重要事件。

每份简报保留生成时间、数据截止时间和引用快照版本。没有足够新内容时不发布伪装成新简报的旧内容。

生成服务不可用时退化为基于有效数据的事实清单；不得生成未经验证的解释和推断。

## 11. 全球局势

- 生产页面默认只读取动态快照。
- 种子事件只用于开发和测试，不进入生产兜底。
- 同一局势的后续进展合并到事件时间线。
- 卡片显示最近新增信息、原始来源和更新时间。
- 无新增进展的事件自动降低优先级。
- 影响链严格区分事实、常见机制与情景推演。
- 旧事件允许留在观察区，但不能标记为“刚刚发生”。

数据或生成服务失败时，页面仍可展示最后一份有效且明确标记为延迟的快照；从未成功时显示不可用状态。

## 12. 新闻详情与学院

新闻详情继续读取真实新闻快照。「所以呢？」只在结构化分析证据充分时展示，并维持专业解读、因果链、预期差、反例及动态个人影响规则。

学院课程保持静态。课程中的“今日案例”只能连接当前新闻或全球事件快照；没有合适事件时隐藏案例入口，不回退到演示新闻。

## 13. 更新频率

- 新闻和全球局势：每小时。
- 汇率及可获得的全球市场数据：每小时。
- A股、港股和美股指数及行业：交易时段每小时；收盘后保留当日收盘快照。
- 市场简报：北京时间早间一次，主要市场收盘后一次。
- 重大政策和地缘事件：随每小时新闻任务重新评估。

GitHub Actions 应避免重复部署风暴；数据提交完成后只触发一次对应 Pages 部署。

## 14. 缓存与刷新

- JSON 请求附加快照版本或时间参数，并使用重新验证策略。
- Service Worker 不得对动态 JSON 使用缓存优先。
- HTML 和静态资源继续使用内容哈希。
- 页面重新获得前台焦点，或超过数据集刷新间隔时，重新检查状态索引。
- 提供手动“检查更新”。
- 不进行高频轮询。

## 15. 页面和移动端

全站顶部提供统一数据状态入口，展示最近全站更新、各数据集成功时间、失败来源、下一次预计更新和降级说明。各页面仍就近显示对应数据的 `dataAsOf`。

移动端要求：

- 市场标签可横向滚动。
- 指数卡片优先显示价格、涨跌幅、时间和状态。
- 来源及延迟信息保持可见，不能只存在于悬停提示。
- 行业列表默认显示前 5 和后 5。
- 简报按内容层级渐进展开。
- 全球局势地图在小屏转为地区列表。
- 复用现有字体、玻璃卡片、颜色和响应式系统。

## 16. 测试

自动测试覆盖：

- 统一状态契约及各数据集独立失败。
- A股、港股、美股和全球资产分组。
- 交易时段、休市、上一交易日与时区边界。
- 单位、币种、时间和涨跌幅校验。
- 行业分类体系与市场一致。
- 缺乏证据时不得生成波动原因。
- 首页不再导入演示市场和行业数据。
- 简报只引用当前有效快照。
- 全球局势生产环境不回退种子事件。
- Service Worker 不缓存动态 JSON。
- 页面重新聚焦后的条件刷新。
- 桌面和移动端的切换、筛选、展开与更新时间显示。

部署前运行全量测试、类型检查、生产构建和数据验证。部署后抽查每个市场、行业、简报、全球局势、状态入口以及移动端，并对照公开快照和原始来源。

## 17. 验收标准

- 首页、市场简报和全球局势均读取动态快照。
- A股、港股、美股和全球资产有独立状态与来源。
- 行业强弱随市场切换，不混用分类。
- 所有生产数据可追溯到已验证来源。
- 公开页面不再把演示数据呈现为今日数据。
- 新快照部署后无需等待旧缓存自然过期即可读取。
- 数据不足时显示缺失，不以弱来源或固定文案补齐。
- 摘要、传导和简报明确区分事实、市场解释和推断。
- 全量测试、类型检查、构建、数据验证及线上抽查全部通过。

## 18. 实施分阶段

1. 统一状态索引、缓存策略和生产演示数据隔离。
2. 市场及行业来源验证、数据适配器和快照发布。
3. 首页市场模块动态接入。
4. 动态市场简报和全球局势生产降级改造。
5. 全站状态入口、移动端、回归测试和线上审计。

每阶段产生独立可验证提交，不在单次变更中混入无关重构。
