# Financial Lens：ChatGPT 套餐通道隔离验证设计

日期：2026-10-13（北京时间）

状态：设计已于 2026-10-13 获用户确认；实施计划待审阅。尚未完成登录、模型调用或生产接入。

目标分支：`codex/chatgpt-plan-trial`。原站继续使用 `main` 上的 Groq 与 GitHub Actions。

## 1. 目标与成功定义

验证用户自己的 ChatGPT 套餐能否通过官方 Sign in with ChatGPT（SIWC）授权，支持 Financial Lens 的一条新闻生成与审核。不是将 Codex 已有登录凭据改装为网站 API，也不是启用单独付费 API。

成功需要分别证明：

1. 用户在官方页面授权，身份与套餐使用权限均验证通过。
2. 使用该授权读取实际可用模型，并完成一次低输出量的连接探针。
3. 对一条已有可靠来源的新闻执行证据提取、解读生成和另一请求的审核。
4. 本地结构与证据门槛通过，开发验收再对照原文检查内容；生成成功不等于内容合格。
5. 原 Groq 通道、生产快照、页面和定时任务未改变。

登录成功、读到模型、完成生成、内容验收是四个不同结果，报告不得混用。

## 2. 已确认约束与不包含内容

- 不新增付费 API、付费服务、购买额度或自动付费兜底。
- 套餐调用仍消耗账号可用额度，可能影响其他应用；不承诺无限使用、每天数量或永不重新授权。
- 官方通道可能使用套餐额度或账号可用 credits，不能承诺请求参数能强制只消耗套餐包含额度。真实调用前须让用户核对应用额度设置；不接受其额度规则时停止试验，不自动购买。
- 用户自行完成身份验证、账号选择及权限确认。助手不操作登录表单或代替用户批准权限。
- 不读取、导入或复制现有 Codex/ChatGPT 的登录文件、浏览器 Cookie、已有密钥。
- 不变更 Financial Lens UI、新闻来源白名单、行情或研报功能。
- 第一阶段仅本地人工启动试验，不新增定时任务，不发布模型结果，不修改 GitHub Pages。
- 不把本地验证成功称为关机后的云端自动运行已完成。
- 当前未在项目检索到 LICENSE。公开仓库不自动等于已明确开源许可；正式分发或以开源应用身份发布前，需确认许可与适用资格，不擅自添加覆盖整个项目的许可证。

## 3. 隔离与组件边界

选择独立本地试验入口，而不是直接替换生产 provider。现有工作流在 `main` 上运行，不为试验分支增加发布权限。

试验代码规划放在 `experiments/chatgpt-plan/`；若需 SDK，使用独立依赖清单及锁文件，不为试验修改生产依赖。优先采用官方 SIWC 本地 SDK，并在实施时核验其版本、可用性、许可与凭据保护行为。核验不通过则停止并报告，不改用非官方逆向接口。

组件职责：

- 授权连接：管理本应用自己的 host ID、PKCE、身份校验与单账号会话。
- 受保护存储：保存本应用新授权的会话与更新后的刷新令牌，不暴露给页面或报告。
- 模型目录：读取当前授权账号的模型，不凭套餐名称猜模型权限。
- Responses 传输：接收阶段请求，处理流、终止事件、超时和额度错误。
- 新闻试验入口：使用既有来源与领域校验，控制单篇样本及请求预算。
- 验收报告：只保存来源、日期、哈希、模型标识、阶段状态与必要短引文、合格输出。

第一阶段不将 OAuth token 填入旧的 `apiKey` 参数，也不伪造 Groq 模型名称来通过硬编码审核门槛。传输、生成结果和审核来源必须如实区分。

可以暴露或抽取现有纯提示构建、证据 ID 映射与领域验证函数供试验复用；不得为此放宽事实、因果、个人影响或缓存撤下规则。生产默认调用和既有测试保持不变。

## 4. 官方授权流程与凭据保护

使用公开发现配置与官方授权、令牌、JWKS 端点。只允许 HTTPS 官方端点；回调监听仅绑定 `127.0.0.1`，路径 `/auth/callback`，使用可用端口。

每次尝试生成新的 state、nonce、PKCE verifier/challenge；监听先启动，再由用户打开授权页面。单次监听最多五分钟，只消费一次匹配的有效回调；拒绝错误 state、重复回调和跨会话结果。超时结束当前尝试，用户可主动重新发起，不自动弹出登录循环。

首次动态注册使用 `dynamic_agent_client`，应用名称如实标为 Financial Lens；保存回调颁发的 client ID，而不是将注册入口 ID 当成长期 client ID。此 host 的 opaque host ID 保持稳定。

按官方契约请求身份及套餐权限。校验 ID token 的签名、issuer、audience、有效期与 nonce。只有实际获授 `chatgpt.tokens.use.direct` 等调用所需权限时，才允许模型请求。仅验证身份不能算授权成功；拒绝授权时结束，不调用模型。

凭据存放在项目之外的应用专用用户运行目录，由 SDK 或存储层落实当前用户专有权限。先检验目录与文件权限，再写入会话；Linux 使用 owner-only 权限，Windows 验证当前用户专有 ACL。无法落实保护则仅保持内存会话，不持久化，不宣称重启后可自动使用。

实施时先为本应用确定专用位置，不复用 Codex 配置目录。初始化权限属于单独可核验步骤；不使用未校验变量或宽泛目录进行删除、移动、权限重置。

access/refresh/ID token、授权 code、verifier、账号身份资料不得进入源码、public/data、浏览器存储、Git、截图、日志或验收报告。回调地址及含 ID-token hint 的授权地址不得原样记录。诊断输出只使用固定错误类别。

刷新近到期会话时串行执行，原子保存最新替换令牌；撤销或 invalid_grant 时停止并要求重新授权，不反复重试。退出时尝试官方撤销，清除本应用本次授权的凭据；撤销未确认须告知用户。

## 5. 模型与 Responses 适配

授权后通过官方 `/v1/models` 读取账号目录。保留模型的实际 slug，用户明确选择生成与审核模型，不擅自迁移到所谓最新模型。

优先使用两个不同的可用模型分别生成与审核。若只有一个可用模型，只允许连接探针；不得将同模型重复调用称为已完成独立审核，单篇验收停留为条件不足。

仅调用公共 `/v1/responses`，不调用 ChatGPT backend-api。请求使用 `store:false`、`stream:true`、完整 input 上下文和 instructions/developer 消息。不得照搬旧 Chat Completions 的 system 消息、temperature、max_completion_tokens 等参数。

适配器遵守当时 SIWC 预览限制，不发送 background、max_output_tokens、previous_response_id 等未支持字段。结构化输出格式须经过真实能力验证；模型不支持所需格式时停止，而不是静默改用猜测式 JSON 修复或放宽校验。

SSE 解析必须正确处理任意分块、多事件、UTF-8 与终止状态。只在 `response.completed` 后接受完整文本，再解析 JSON 和执行领域检查。response.failed、incomplete、断流、拒绝或取消都不是成功。

试验限制：连接探针最多一次模型请求；单篇新闻最多四次阶段请求（证据、分析、审核，以及至多一次有依据的修复），同次试验总上限五次。禁用 SDK 隐式请求重试，修复同样计入预算。只对一条来源样本运行，不循环新闻队列。

单篇来源文本最多 6,000 字符，每次请求最长 90 秒，响应流累计最多 256 KiB，超过任一限制停止并标为不完整。客户端取消不等于服务端 token 计费上限；本路线不支持的 max_output_tokens 不能用于承诺硬额度控制。用户可在官方设置限制应用额度，本工具不替用户购买或调整额度。

## 6. 单篇新闻与内容验收

试验前固定来源 URL、原题、发布时间、抓取时间、证据范围与来源哈希。仅使用现有允许来源；历史回归样本明确写原日期，不冒充今日新闻。

完整正文实际读取后才能标为 full-body；只有 RSS 摘要时标为 summary，明确背景和市场共识未提供。不补政策动机、分析师观点、制裁背景或未报道数据。

复用证据配对、数字、语言、因果相邻边、六维影响评估、反例和撤下检查。个人影响只选强相关维度，通常 2–5 项，允许仅一项，不补股票关系或弱相关内容凑数。

保留既有「所以呢？」的专业解读、类比、传导、机制、真正重点、预期差、反例和个人影响结构。每个观点区分报道事实、常见机制与条件推演；每个判断给出观察项和失效条件。

开发验收逐段核对类比、为什么、反例、市场信号及个人影响，不只核对事实清单。更换模型不自动解决当前审核覆盖缺口，也不证明所有文章正确；这个阶段不作网站全部要求已完成的声明。

试验报告写入独立且 Git 忽略的本地输出目录，不能覆盖任何 public/data 文件。只保存必要短证据和生成结果，不保存媒体全文或身份凭据。发现不合格内容标为 rejected 并说明类别，禁止进入发布流程。

## 7. 错误处理与验收清单

默认 fail closed：无授权、缺权限、账号不具备资格、模型缺失、使用限额、刷新失败、协议错误或语义拒绝均停止当前试验。输出固定阶段/类别与下一步，不输出原始认证响应或令牌。

ChatGPT 试验失败不触发 Groq 或付费 API 兜底；原网站的独立 Groq 定时任务仍继续。试验进程不得修改或停止原任务。

实施验收必须包含：

- OAuth state/nonce/PKCE、错误 audience/issuer、缺权限、拒绝和重复回调的反向测试。
- 存储权限、忽略规则、刷新并发和日志脱敏测试。
- 不支持参数未发送、模型不匹配拒绝、SSE 分块与失败终止、请求上限测试。
- 使用真实失败新闻样本的证据与归属回归；未经审核的输出不能写生产目录。
- 原 Groq 路径的全套回归、构建、数据契约及现有工作流差异检查。
- 用户亲自授权后的模型目录与真实 terminal event 验证，不能用模拟结果宣称接入成功。

## 8. 后续生产接入边界

本地成功后，另行决定运行环境、许可、持续刷新、凭据撤销、发布审批及回滚策略。

官方说明支持自托管 VM，但需要受保护会话与独立稳定 host ID。是否已有无需新增费用的持续运行环境，尚未由用户提供；第一阶段不采购、开通或承诺免费的云主机。

现有 GitHub 临时 runner 是否适用、刷新会话如何可靠保存以及托管服务的资格，均未实测。因此本设计不将 OAuth token 加入现有 Actions，不承诺电脑关闭后这条新通道已经自动运行。公开应用不得共享所有者的凭据供他人直接调用；其他使用者分别授权自己的账号。

进入自动发布或合并 main 前，需要单独确认生产设计与语义验收，保持原运行方式可回退。
