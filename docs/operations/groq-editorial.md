# Groq complete-body analysis

Configure repository Actions secret `GROQ_API_KEY`, keep the account on Free, and do not upgrade or enable paid fallback. The hourly data workflow uses only Groq for automatic analysis; Cerebras is not retried.

The fixed endpoint is `https://api.groq.com/openai/v1/chat/completions`. Evidence and generation use `openai/gpt-oss-120b`; the review request uses a distinct `openai/gpt-oss-20b` model. Both use low reasoning and strict JSON schema. No browser search or execution tools are enabled. Secrets never enter public files or article prompts. Keep the Groq account on Free; the application cannot enforce account billing settings.

The hourly workflow shares one twelve-request budget across at most two deep analysis attempts (including historical migration) and two factual-summary/translation attempts, with at least 60 seconds between requests. Chinese publisher summaries allowed by source policy need no model calls. Independent generated summaries require both generation and semantic review; failure to create a deep analysis does not remove an already valid summary. Complete bodies or attributed publisher summaries are accepted; summaries are explicitly marked and never imply full-body reading. Deep generation preserves extracted facts and allows a single revalidated repair.

The distinct review model returns per-fact, per-edge and per-impact verdicts, a conditional-scenario verdict and bounded failure codes. Every selected personal dimension also needs a material relevance score, affected audience/region, source trigger, transmission path and invalidation. Consumer spending means households, not corporate procurement. Publication requires every check to pass and no findings. The models share a family and may share mistakes; this is not independent source corroboration or proof of truth. Historical reviews retain dated pending status during outages; rejected interpretations are withdrawn and cannot be restored from the older review file. Unchanged summaries and editorials cache independently by source identity and processing version.

Public `editorial.evidence` contains short evidence quotations, not the full body. `analysisAttempt` tracks hash-bound retry counts, capped at three for an unchanged body; less-attempted candidates receive priority so failures cannot permanently block other articles. Source health exposes passed `stages.evidence`, `stages.analysis`, `stages.audit`, rejection categories and published `itemCount`. All rejected attempts report error even when the API is reachable. API connectivity and successful editorial publication are different results.

Network errors, timeouts, HTTP 408/429 and 5xx stop model work for the run without consuming a content-rejection attempt. No paid provider is used as fallback. Visible frontend pages poll published snapshots every five minutes, pause polling when hidden, check on return, and avoid overlapping requests. This does not make hourly GitHub Actions a real-time feed or guarantee scheduling punctuality.

The provider's explicit json_validate_failed response is a per-stage protocol failure, not a source fact rejection: it does not stop other summary candidates. Unrecognized 400 errors still stop safely. No secret values or rejected model prose are logged. The production workflow no longer reads legacy translation endpoint/key secrets.

Source publication policies compile from the reviewed registry (`npm run sources:generate`); normal builds check that the generated policy matches the registry. Exact allowed hosts and article paths are checked at runtime along with review validity dates. Unknown permissions remain excluded from independent summary publication rather than inferred from a well-known brand.

`news-acceptance.json` records distinct scheduled cycles and actual current content categories, request bounds and stage failures. Manual runs do not count as three scheduled cycles. Runtime structure checks never replace development review against real original sources, or claim that all future model interpretations are correct.

Market observations must carry the actual source timestamp. Empty source numbers are not zero, future observations are rejected, and an intraday observation is never inferred to be a closing quote merely because its date matches today. Regular closing times are a conservative fallback; early closes are not inferred without explicit provider state. Retaining older observations does not advance the last-successful-fetch timestamp.

Deployment alone is not proof of model operation. Inspect actual data-job source health (`groq-editorial`: attempted, generated itemCount, rejected, failures) and generated body-bound editorials. Reader/source coverage and stock quotations are separate work; this adapter does not make feed-only articles complete.
